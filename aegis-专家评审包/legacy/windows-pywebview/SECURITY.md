# 安全策略（Security Policy）

本文档说明 Aegis 浏览器的**威胁模型**、关键安全机制，以及如何负责任地披露漏洞。
所有声明均基于已落地的代码，不夸大、不隐瞒局限。

---

## 一、威胁模型

**防御的目标**

- 中间人篡改更新通道，向用户推送恶意安装包（最高危）。
- 钓鱼/恶意站点诱导用户交出凭据或下载木马。
- 明文传输的同步凭据被窃听。
- 本地恶意脚本/配置文件注入（通过主页、会话恢复、IPC）。
- 真实内网 IP 经 WebRTC 泄露。
- 危险可执行文件被静默下载并运行。

**明确不在范围内的（受内核/架构约束）**

- 浏览器内核（Chromium）自身的漏洞——由 QtWebEngine 上游负责，Aegis
  跟随其发版节奏，无独立热补丁通道。当前锁定 `PySide6==6.11.1`（随附
  QtWebEngine 捆绑 Chromium 接近 140，2026 水平）；早期误锁 `6.7.3`
  （仅 Chromium 118）已纠正。
- Chrome/Edge 扩展生态——QtWebEngine 不开放对应 API。
- 操作系统级攻防（提权、内核漏洞）——壳层代码无法覆盖。

---

## 二、关键安全机制

### 1. 签名更新信任链（防更新器 RCE）

- 发布方用 **离线持有的 Ed25519 私钥** 对更新清单（manifest）签名。
- 客户端**写死对应公钥**（`app/updater.py` 的 `UPDATE_PUBLIC_KEY_B64`）。
- 流程：**先验签 → 再比版本 → 才下载 → 下载后再次 SHA-256 复核**。
- manifest 与安装包地址**强制 HTTPS**；可选对更新服务器证书做 SHA-256 锁定。
- 公钥未配置时**宁可错过更新，也不接受任何未验签来源**。
- 私钥生成与签名在 `tools/sign_release.py`，**私钥永不进仓库**（`.gitignore`）。

### 2. 安全浏览（防钓鱼/恶意站点）

- 内置真实 typosquat 种子名单 + 可插拔情报源（本地黑名单 / Google Safe Browsing API v4）。
- 覆盖度**如实告知**用户：仅种子名单时，仪表盘与状态会明确提示"建议接入真实情报源"。
- 不在能力不足时假装已保护。

### 3. 传输安全

- 同步（WebDAV）强制 HTTPS，Bearer Token 优先，依赖系统 CA 校验。
- HSTS 预加载：名单内主机 `http://` 自动强升级 `https://`，证书错误不可绕过。

### 4. 本地攻击面收敛

- 所有外部导航入口经 `app/security.safe_url()` 的 scheme 白名单（`file:`/`javascript:` 等拒绝）。
- 单实例 IPC 带随机令牌认证，无令牌连接丢弃。
- 配置文件逐字段类型 + scheme 校验，拒绝 `javascript:` 主页等注入。
- 危险下载（exe/bat/ps1/...）二次确认，默认取消，绝不自动运行。
- 密码无加密能力时整体禁用，绝不降级明文。

### 5. 隐私

- WebRTC 默认仅暴露公网接口（防真实 IP 泄露）。
- 无痕模式离屏 profile，历史/Cookie/缓存/密码不落盘。
- UA 如实声明 `Aegis/<version>`，不伪装 Chrome。

---

## 三、安全自测

`tools/selftest_security.py` 对上述机制的可验证逻辑做离线断言（无需 GUI），
覆盖：安全浏览、HSTS、配置校验、同步加密、签名更新信任链。
运行：`python tools/selftest_security.py`。

---

## 四、负责任披露

如发现 Aegis 的安全漏洞，请通过以下方式私披露（**勿在公开 Issue 直接贴 PoC**）：

- 邮件：`security@aegis.example`（占位，发布前替换为真实地址）
- 加密：使用仓库公布的 Ed25519 公钥（与更新签名同源）封装报告

我们会在确认后优先修复，并在变更记录中致谢（如你同意）。

---

## 五、已知局限（与威胁模型对应）

详见 `README.md` 第七节。重点：内核补丁节奏、威胁情报覆盖、扩展生态、
站点隔离粒度、密钥保护强度、代码签名信誉——均受上游/架构约束，
Aegis 以"如实声明 + 提供可配置增强项"的方式处理，而非假装已解决。
